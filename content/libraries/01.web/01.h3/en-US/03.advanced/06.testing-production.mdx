# Testing and production

h3 keeps request handling close to `net/http`, so most tests can use `httptest` without opening a listener. Lifecycle behavior deserves separate tests because it owns listeners, goroutines, and cleanup order.

## Test a standalone router

```go
func TestUserRoute(t *testing.T) {
	router := h3.NewRouter()
	router.HandleFunc("GET /users/{id}", func(w http.ResponseWriter, r *http.Request) {
		_, _ = w.Write([]byte(r.PathValue("id")))
	})
	router.Build()

	request := httptest.NewRequest(http.MethodGet, "/users/42", nil)
	response := httptest.NewRecorder()
	router.ServeHTTP(response, request)

	if response.Code != http.StatusOK || response.Body.String() != "42" {
		t.Fatalf("response = (%d, %q)", response.Code, response.Body.String())
	}
}
```

The explicit `Build` is part of the test. It catches invalid or conflicting patterns and ensures the test exercises the same compiled middleware chain used in production.

## Test App behavior without a port

`App` can be called as an `http.Handler`. Build the router, then use `httptest` to verify response metadata and custom fallbacks:

```go
router := h3.NewRouter()
router.HandleFunc("GET /health", func(w http.ResponseWriter, _ *http.Request) {
	w.WriteHeader(http.StatusNoContent)
})
router.Build()

app := h3.New(h3.Options{Router: router})
response := httptest.NewRecorder()
app.ServeHTTP(response, httptest.NewRequest(http.MethodGet, "/health", nil))
```

This does not test listener creation, TLS handshakes, or servlet lifecycle. Keep those as focused integration tests. `Addr: "127.0.0.1:0"` is useful for lifecycle-only tests, but `App` does not expose the resolved listener address; tests that make client connections must choose an explicit test address or run the server behind a process-level integration boundary.

## Lifecycle tests

For every servlet, verify at least these sequences:

| Sequence | Expected property |
| --- | --- |
| `Start` → `Stop` | All resources and goroutines are released before `Stop` returns. |
| `Start` → `Stop` → `Start` → `Stop` | Per-run cancellation state is recreated correctly. |
| cancelled startup context | `Start` returns promptly without leaving live resources. |
| later servlet fails to start | Earlier servlets can be rolled back safely. |
| repeated defensive `Stop` | No double-close panic or double-free when the component promises idempotence. |

Run `go test -race ./...` for components and middleware that capture shared state. The router's atomic snapshot does not protect state inside handlers, middleware, or servlets.

## Production checklist

- Set an explicit address and appropriate HTTP timeouts.
- Apply request body limits independently from `MaxHeaderBytes`.
- Install recovery, request identity, authentication, security headers, observability, and rate limits as explicit middleware.
- Keep route configuration single-writer and build before publishing readiness.
- Ensure `Stop` cannot wait forever on a worker that ignores its owned stop signal.
- Track hijacked connections and other resources outside `http.Server.Shutdown`.
- Treat `OnStopped` as notification; keep cleanup in servlet `Stop`.
- Report startup, serving, and shutdown errors to process supervision.
- Test TLS certificate callbacks with real handshakes when certificates are selected dynamically.

## What h3 deliberately does not decide

h3 does not define a health model, readiness barrier, central error type, renderer, validation policy, trusted-proxy policy, or observability backend. Those decisions need application context. Keep them explicit and test them at the boundary where they are introduced.
