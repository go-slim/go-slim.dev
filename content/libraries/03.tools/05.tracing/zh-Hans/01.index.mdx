# tracing

`go-slim.dev/tracing` 是面向 Go 业务代码的进程内观测库。它提供 trace、span、event、结构化业务 log、有界非阻塞采集、本地分段存储，以及标准 `net/http` 查询和实时流接口。

<Callout title="不是 OpenTelemetry">
  tracing 不是 OpenTelemetry 或 W3C Trace Context 实现。它不提供跨进程传播、远程 exporter、采样协议或指标采集。
</Callout>

## 安装

```sh
go get go-slim.dev/tracing
```

根包只依赖标准库。`tracing/storage` 和 `tracing/http` 提供存储与查询表面。

## 包方向

依赖方向是有意固定的：

```text
business -> tracing <- tracing/storage <- tracing/http
```

业务代码导入根包并产生观测记录。storage 通过 handler 边界消费 batch。HTTP 读取 storage engine 并暴露查询/流式接口。

## 记录什么

```text
Tracer.Start
└── Trace
    └── Span
        ├── Span
        ├── Event
        └── Log
```

当应用需要围绕 HTTP 请求、队列任务、后台 worker 或领域流程做本地业务观测时，使用 tracing。

## 适合的问题

tracing 适合回答业务向问题：

- 哪个操作触发了这个后台 job？
- 哪个 span 产生了这个领域 event？
- 一个 workflow 内发生了哪些 service-level log？
- 即使 export/storage 后续丢弃记录，handler 是否产生过 trace？

它不是基础设施 telemetry 的替代品。需要跨进程标准、远程 exporter、采样控制、dashboard 或告警集成时，应使用 OpenTelemetry、metrics 或日志系统。
